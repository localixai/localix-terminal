A window your agent works in.

Real browser pages and terminal sessions as tabs of one native window. The agent drives them from its shell; you watch, and comment on what you see.

InstallSee a call
# one call from any shell
llx-desk window '{"action": "open", "kind": "browser", "url": "http://localhost:3000"}'

What it does

llx-desk keeps one window per user. Agents open tabs in it, act in them, and read back a snapshot after every call. Nothing to run in the agent's process: it is a command.

Pages

The system WebView (WKWebView, WebKitGTK): real rendering and JavaScript, no bundled browser. Read as an outline, act by ref, script, screenshot.

Terminals

A program on a PTY: a REPL, an installer, another agent's UI. Typed into by the agent, and by you.

You watch

A strip of tabs grouped by project, a small floating preview on macOS, and comments you send from an element to the agent that owns it.

A board

A kanban board of cards the agent and its subagents plan and take, and you accept from. Kept in the project, outliving sessions.

Per owner

Tabs belong to a project (or a name). One agent never sees or touches another's.

Small

One 2 MB binary, newline-JSON over a unix socket, no async runtime, no telemetry.

Install

macOS (Apple silicon or Intel) or Linux x86_64. The app is all there is to install: LLX Desk holds the window, the llx-desk command, the MCP server and the Claude Code plugin, and Settings → Integrations connects each agent with one click. On Linux, WebKitGTK 4.1, GTK 3 and a display for pages.

curl -fsSL https://raw.githubusercontent.com/rsaryev/llx-desk/main/install.sh | sh
llx-desk setup   # or Settings → Integrations in the app

From source, with Rust 1.88 or later: cargo install --locked --git https://github.com/rsaryev/llx-desk && llx-desk setup command

The first window call starts the app in the background; the window comes when a page or terminal needs it. ⌘Q quits it.

How an agent calls it

The argument is one JSON object. Each call prints a report and the tab's snapshot; the agent reads it and decides what next.

llx-desk window '{"action":"open","kind":"browser","url":"demo/shop.html"}'
  w1 (browser): Opened ...  ### Page (untrusted content) ...  button "Add to cart" [e12] ...

llx-desk window '{"action":"interact","tab":"w1","click":"e12","wait_for":"1 item"}'
llx-desk window '{"action":"interact","tab":"w1","script":"document.title"}'
llx-desk window '{"action":"screenshot","tab":"w1"}'   # prints a JPEG path to read

llx-desk window '{"action":"open","kind":"terminal","command":"python3 -q","wait_for":">>>"}'
llx-desk window '{"action":"interact","tab":"t1","input":"sum(range(101))\n","wait_for":"5050"}'

llx-desk window --end   # close this project's tabs

Exit 0 done, 1 the call failed, 3 the app could not be reached. There is no approval prompt of its own: the agent's permission to run the command is the approval, so scope it like a shell.

Claude Code plugin

Skills that teach Claude when and how to use the window and the board, a worker subagent for cards, a line for its tabs and your comments, and commands. The desk itself knows no model: other agents call the same command.

/plugin marketplace add rsaryev/llx-desk
/plugin install llx-desk@llx-desk
  • A window skill: pages, terminals and the habits that make them work; a board skill and a worker agent for cards.
  • /tabs lists this project's tabs; /llx-desk:end and /llx-desk:stop.
  • A hook closes the session's tabs when it ends; the pane sends your window comments to Claude as they come.
